# S2 — bus interface: BiSS-C, SSI, SPI (2026-10-20)

Study by an agent (Opus 5.5), text only. Labels: [V] read in a primary source, [U] uncertain, [C] computed here.

## BiSS-C slave requirements (point-to-point, sensor only)

Source: BiSS C Protocol Description Rev D2, 2023-11-08, https://biss-interface.com/wp-content/uploads/2025/10/BiSS_C_protocol_D2en.pdf.
The unidirectional A3 profile (https://biss-interface.com/wp-content/uploads/2024/07/BiSS_C_unidirectional_protocol_A3en.pdf) is "not recommended for new designs" [V].

| Item | Requirement | |
| --- | --- | --- |
| Pins | MA in, SLO out; SLI tied low inside; MO unused | V |
| Edges | slave drives SLO on the rising edge of MA; master compensates line delay | V |
| Frame | idle 1 · ACK 0 (2nd rising edge after LAT) · START 1 · CDS · data MSB first · nE, nW · CRC · stop 0 for the timeout · 1 | V |
| Data | ≤ 64 data bits, CRC ≤ 16; typical MT, ST, ERR, WRN, CRC-6 | V |
| Status | ERR, WRN active low (profile BP3); all-zero data = Null Value (invalid) | V |
| CRC-6 | x⁶+x+1 (0x43), start 0, covers data + ERR/WRN, sent inverted MSB first | V (start value from secondary sources and moteus) |
| Latch | data generation starts on the first rising edge (LAT) | V |
| t_busy | LAT to START: min 2·T_MA, max 40 µs; SLO held 0 after ACK until ready | V |
| MA | 80 kHz to 10 MHz; every slave supports 250–1000 kHz; min high/low 40 % of T_MA (40 ns at 10 MHz) | V |
| Timeout | static 12.5–40 µs ("often about 20 µs"); adaptive ≈ 1.5·T_MA optional; CDM sampled at the end of the timeout | V |
| Line delay | 0–40 µs, jitter ±25 % T_MA | V |
| Cycle | min cycle every slave supports 250 µs; 40 µs wait after power-on or error | V |
| Register access | CDM/CDS bits form a control frame: S, CTS, 3-bit ID, 7-bit ADR, CRC-4 (0x13, inverted), R/W, data bytes; CDM=0 for 14 cycles resets; t_busy_r ≤ 20 ms | V |
| Mandatory registers | Profile ID ≠ 0 at 0x42–0x43 if no EDS; Manufacturer ID at 0x7E–0x7F must be implemented with an ID assigned by iC-Haus or the BiSS Association; DEV_ID 0x78–0x7D and DEV_SN 0x44–0x47 may be zero | V |

A minimal slave cannot omit register access under D2: the mandatory IDs are read only through CDM/CDS. Decision for R1:
implement the D2 control channel with read-only fixed addresses 0x40–0x7F, no EDS (a few hundred flip-flops [U]).

Line levels: D2 recommends RS-422 [V]. R1 has 3.3 V CMOS pads; the board carries one full-duplex RS-422 transceiver
(receiver for MA, driver for SLO; 10 Mbit/s rating to be checked [U]). Pad and transceiver delay count as line delay.

Clocking: shift the frame from MA directly; timeout counter from the on-chip oscillator (20 µs nominal, ±30 % RC spread
gives 14–26 µs, inside 12.5–40 µs [C]); freeze the latest angle at LAT; t_busy = 2·T_MA. Data age ≤ one update period (S1).

## Licence

The slave is written from the public protocol description. Registration with the BiSS Association and the assignment
of a Manufacturer ID are handled outside this repository; until then `MFR_ID` is a register reset value. BiSS Line
(single pair, 8b/10b 12.5 MBd, FEC) is out of scope for R1.

## SSI and what open controllers consume

SSI: clock idles high; first falling edge latches; MSB first, n bits, Gray or binary; no CRC; data low for the monoflop
time (typ. 15–25 µs) after the last bit; clock typically ≤ 1.5–2 MHz [U]. D2 states point-to-point BiSS is
hardware-compatible with SSI [V]. Mode selected by register, not auto-detected.

| Controller | Encoder inputs today |
| --- | --- |
| moteus (Apache-2.0) | SPI (AS5047, MA600/732, iC-PZ, Orbis, AMT22), I2C, quadrature, sin/cos, hall, UART, BiSS-C over RS-422 (https://mjbots.github.io/moteus/reference/encoders/) |
| ODrive S1/Pro | ABZ, hall, SPI (AS5047/48, MA732/702, AMT23), RS-485, RS-422 SSI (experimental); BiSS-C experimental on Pro (https://docs.odriverobotics.com/v/latest/hardware.html) |
| Tinymovr | SPI (MA7xx, AS5047, AMT22), hall |
| SimpleFOC | SPI, I2C, analog, PWM, ABI, UVW; SSI via drivers library |
| VESC (GPL-3.0) | hall, ABI, AS5047, MT6816/6835, TLE5012, AMT22, sin/cos, PWM, Tamagawa, BiSS-C (`enc_bissc.c`) |

Tamagawa T-format, Nikon A-format and EnDat (HEIDENHAIN licence [U]) are excluded.

Pins: BiSS-C/SSI 2 (MA, SLO) + SPI 4 (SCLK, SDI, SDO, CSn) = 6; ABZ would add 3 (cut 1 in PLAN.md). Option: make the
SPI angle read frame-compatible with the AS5047P 16-bit format (mode 1, parity) so moteus, ODrive, Tinymovr and
SimpleFOC read R1 with existing drivers [U].

## Test strategy (protocol testbench)

1. CRC-6 vectors (18-bit position, nE=nW=1) [C], cross-checked against the moteus table: 0x00000 → CRC 0x05, wire 0x3A;
   0x3FFFF → 0x3D, wire 0x02; 0x12345 → 0x32, wire 0x0D.
2. MA 80 kHz to 10 MHz with 40 % duty corners. 3. t_busy = 2·T_MA and START delay when data not ready.
4. Static timeout across RC corners. 5. Back-to-back frames at minimum cycle. 6. Aborted frame + 40 µs recovery.
7. nE/nW and Null Value. 8. CDM/CDS reads of 0x42/0x7E, CRC-4 errors, 14 × CDM=0 reset. 9. SSI Gray/binary and monoflop.
10. Simultaneous SPI and BiSS reads (data consistency).

No open-source BiSS-C slave RTL was found. References: `mjbots/moteus` `fw/bissc_extract.h` + test (Apache-2.0,
scoreboard reference); `ngblume/biss-safety-analyzer` (MIT, decoder); `kamocat/pio_biss` (MIT, RP2040 master for the
bench); `lenzencoders/BISS-C` (MIT, FPGA master); VESC `enc_bissc.c` (GPL-3.0) and LinuxCNC hostmot2 absenc as
black-box masters only; `Hello-FPGA/BISS-C` has no licence, read only.

## Risks

| Risk | Mitigation |
| --- | --- |
| No certified tester | interop against ≥ 3 independent masters (moteus, iC-Haus MB3U/MB4, ODrive Pro or VESC); formal certification via Scherer Technology or PassWorld (cost unknown) |
| Manufacturer ID not yet assigned | `MFR_ID` is a changeable register reset value |
| 3.3 V pads at 10 MHz | simulate pad with board load; MA glitch filter; transceiver on the board; specify max MA per cable length |
| RC oscillator spread on timeout | trim or nominal with margin |
| Data latency | fixed and published; update rate from S1 |
