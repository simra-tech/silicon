# R1 block interface contracts (0.1, 2026-10-20)

Binding for revision-2 work. A change needs a dated row here and in both block READMEs.

| Interface | Contract |
| --- | --- |
| AFE → ADC | Two differential outputs, 1.44 Vpp full input (80 % of the ADC ±0.9 V FS, D16; was 1.6 Vpp / ±1.0 V), common mode 0.6 V from the ADC `vcm2` port; load per side: top-plate CDAC 2.8 pF, 250 ns track window, top plate near 0 V at track start; settling within the track window: non-linear residual ≤ 0.25 LSB at 12 bits; the linear part (a gain error, ≤ ±0.03 % in r1_afe revision D) is removed by the ADC gain/weight calibration and does not count (change 2026-10-20 after revision D: total error 0.38 LSB at the worst corner, 0.25 LSB total needs an output buffer above 1 mA; the host calibration must be re-run or temperature-compensated, since the linear part drifts up to about 0.4 LSB over temperature). |
| isense → ADC mux | Differential ±0.85 V at ≈ 0.57 V CM (gain 14, 40.38 mV pedestal); sampled at the centre strobe `is_smp_a/b` from `r1_ctrl`; same CDAC load as above. |
| isense → safe | The isense differential output drives the four window comparators directly (OC_A, NEG_A, OC_B, NEG_B). |
| safe → ctrl | Four asynchronous flags `oc_a, neg_a, oc_b, neg_b` (active high = input above the cell threshold, 1.2 V domain after level shift); threshold codes `thr_oc[5:0]`, `thr_neg[5:0]` per channel (NEG cell code = 63 − `thr_neg`); per-comparator offset-calibration codes `cal_oc_a[5:0]` etc. summed into the threshold DAC (step VREF/252 = LSB/8, k = 32 no shift); `az_win` strobe from ctrl marks the isense auto-zero window; ctrl runs the calibration search in the zero-current time *after* `az_win` (change 2026-10-20 from T4b: during the window the isense output is not valid) with the gates off, all four comparators in parallel at `thr` = THR_ZERO = 14. Result (change 2026-10-20, ctrl revision 0.3, resolves the mismatch below): two-sided search, k_cal = 32 + round((k_rel + k_trip)/2 − k_ideal), k_ideal = 36.31 (OC) / 27.69 (NEG), implemented as 32 + floor((k_rel + k_trip − `CMP_CAL_IDEAL`)/2) with `CMP_CAL_IDEAL` = 72 / 55 half codes; per decision ctrl applies a preset code (0 for the release pass, 63 for the trip pass) and then the probe code, ≥ 16 ticks each (`AZ_CFG.CAL_STEP`, reset 32 ticks); 14 PWM periods per search. The four code adders and the search live in ctrl; the analog block exposes `cal_*[5:0]` inputs only. |

## Open contract mismatches (2026-10-20, found at the round-2 review)

| Interface | Mismatch | Resolution |
| --- | --- | --- |
| safe → ctrl, calibration search | `r1_safe` revision 3 (README and `sim/cal_model.py`) defines the result as k_cal = 32 + round((k_rel + k_trip)/2 − k_ideal) with k_ideal = 36.31 (OC) / 27.69 (NEG) at cell code 14 (NEG 49, i.e. `thr_neg` = 14), a two-sided search so the hysteresis cancels. `r1_ctrl` revision 0.2 (`rtl/r1_cmpcal.v`) does a one-sided successive approximation and stores the raw toggle code. Applied as is, the OC threshold shifts by about 4.3 steps (0.54 LSB) plus half the hysteresis, so the 0.25 LSB criterion fails. | **Resolved in ctrl revision 0.3 (2026-10-20).** `rtl/r1_cmpcal.v` runs both passes (release with preset 0, trip with preset 63; 6-bit SAR + check each, 14 windows) and stores 32 + floor((k_rel + k_trip − IDEAL2)/2) with the new register `CMP_CAL_IDEAL` (0x3C, 7 bits per type in half codes, reset 72 / 55). A 6-bit integer IDEAL (36 / 28) was evaluated and rejected: 103 of 274 samples one code off. Evidence: Python model of the RTL search vs `r1_safe` `cal_model.py` on the DC MC (51 + 51), corner (5) and transient MC (30) data, 274/274 identical k_cal; RTL on the same comparator tables 274/274 identical to the model (`r1_ctrl/README.md` revision 0.3). Open on the `r1_safe` side: hysteresis in calibration steps at corners (the search no longer depends on it); comparator delay at small overdrive vs the 32-tick probe time. |
| ADC → ctrl, decisions and slices (found by T5 at ctrl revision 0.3, 2026-10-20) | D17 and the "ADC → ctrl" row specify 14 raw decisions and 14 weights per conversion and both slices converting in parallel ({SIN, COS} then {ISA, ISB}, 36-tick frame). `r1_ctrl` revision 0.3 still has the revision-0.2 port: one 13-bit `adc_raw` with one `adc_valid`, 13 weights (`ADC_W0`–`ADC_W12`), and a scheduler that starts the conversions one after the other through `adc_mux`. The position path itself was checked at the 36-tick frame (count-safe at 208 kHz, full accuracy at 100 kHz, `r1_ctrl/README.md` revision 0.3), but not the port. | ctrl revision 0.4: two 14-bit raw ports with their own `valid`, 14 weights (0x50–0x5D, also CRC-covered), scheduler with the D17 frame; `adcw_ref.py` and the ADC model in `tb_top` updated. Not done in 0.3 (priority list of the brief). |
| ADC → ctrl, weights and frame | r1_adc revision 3 needs 14 weights per slice (28 registers); r1_ctrl revision 0.2 has one set of 13–14. The D17 36-tick frame was arithmetically impossible at one decision per tick (R3 frame-arithmetic note). | D18 schedule above; ctrl revision 0.3 implements the 22-tick encoder frame, the stolen current frame at the PWM centre strobe and 2 × 14 weights; r1_adc revision 4 returns to one decision per tick. |
