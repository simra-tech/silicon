# sg13g2_io_padbare — `sg13g2_IOPadAnalog` with a resistor-free core terminal

Derived views of the PDK IO library in which the analog pad's core-side pad
geometry is a pin of its own, `padbare`. Generated by
`make_padbare_views.py` from the PDK files at commit `8437402` (IHP PDK
Authors, Apache-2.0; the generated files carry that origin in their first
line). The approach is the one of iic-jku/ihp-sg13g2-ams-chip-template
`ip/sg13g2_io_custom` (commit `6524ffdd`, Apache-2.0 WITH SHL-2.1); nothing
was copied from there — the script re-derives the views from the PDK so the
LEF, Verilog and liberty stay in step with the PDK revision.

## Why

`sg13g2_IOPadAnalog` reaches the core through `padres`, which sits behind the
587 Ω `rppd` resistor of `sg13g2_SecondaryProtection` (PDK CDL, line 475).
That resistor would corrupt the Kelvin sense (SENSE_P/N) and the device
measurements (G_SHARED, D_STD, D_ELT, HBT_E/B/C). The stock pin `pad` has two
port geometries: the 70 × 3 µm stub at the die-side edge (y = 0–3, all metals)
that the bondpad abuts, and a 24.8 × 1 µm strip at the core-side edge
(Metal2/Metal3, y = 179–180). Both are the same conductor in front of the
resistor. The router will not use a chip-port pin as a core connection, so the
core-side strip is renamed `padbare` (Metal3 only, as in the template).

## What changes, what does not

| View | Change |
| --- | --- |
| `lef/sg13g2_io.lef` | `sg13g2_IOPadAnalog`: core-side PORT removed from `PIN pad`, added as `PIN padbare` (Metal3 26.105–50.875 × 179.71–180). All other macros unchanged. |
| `verilog/sg13g2_io.v` | `sg13g2_IOPadAnalog` gains `inout padbare` with `assign pad = padbare; assign padbare = pad;` |
| `lib/sg13g2_io_{typ_1p2V_3p3V_25C,fast_1p32V_3p6V_m40C,slow_1p08V_3p0V_125C}.lib` | `pin (padbare)` copied from `pin (pad)` (inout, `is_pad : false`, same capacitance and related pg pins) |
| GDS, CDL, SPICE | **unchanged**: the layout cell is the stock PDK cell (`PAD_GDS`, `PAD_CDLS`, `PAD_SPICE_MODELS` stay at the PDK paths). In the layout `pad` and `padbare` are one net, which is what the LVS must confirm (block README, "Checks"). |

## Per-pin choice in `rtl/g1_chip_top.sv`

| Pins | Terminal | Reason |
| --- | --- | --- |
| SENSE_P, SENSE_N, G_SHARED, D_STD, D_ELT, HBT_E, HBT_B, HBT_C | `padbare` | no series resistance in the measurement path |
| TRIP_SET, VREF | `padres` | high-impedance comparator/DAC input and bandgap monitor output; 587 Ω is harmless and keeps the secondary protection diodes in the path |

Regenerate (inside the container, working directory the block):

```
python3 ip/sg13g2_io_padbare/make_padbare_views.py
```
