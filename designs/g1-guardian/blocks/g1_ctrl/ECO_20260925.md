## Changes

Line numbers: "was" = `rtl/`, "now" = `rtl_eco_20260925/`.

**1. Oscillator cannot be stopped (M1).** `g1_regfile.v` was :110, :124, :148,
:165, :257; now :116, :130, :155, :175, :267. `osc_en` is `1'b1` (synthesises
to a tie cell); `OSC_CTRL` keeps `OSC_TRIM[3:0]`, bit 4 reads 1 and writes to it
are ignored. The optional key-protected "oscillator off" test mode was **not
implemented**: no measurement or bench plan in the repository stops the
oscillator, and its state flop (TMR, ~8 flops with the key logic, under the
20-flop limit) would power up random with `por_n` tied high, i.e. reintroduce
a dead-clock state that only an asynchronous `EN` term could clear. An analog
oscillator failure still removes all protection (no clock-loss detector).

**2. Inrush window cannot be re-opened (M2).** `g1_trip_timer.v` was :78-80,
:138, :153-156; now :81-84, :143, :158-164. New flop `inrush_done`: set when
the window ends, cleared only by a retrigger re-enable or reset;
`inrush_active = ~inrush_done & (inrush_cnt < INRUSH×512)`. The requested form
"counter saturates at 0x1FFFF, mask = counter < limit×512" alone was simulated
and **does not remove the hazard**: a raise within 13.1 ms of the window start
still re-masks (R2 on that variant: 9130-cycle trip latency, failed;
`run_eco.sh alt-inrush`, log `tb_redteam_on_eco_alt_saturate.log`). Semantics
now: a raise while the window runs extends it (E2: 2048 cycles), a lower value
ends it early, a write after it ended acts at the next re-enable or `EN` rise.

**3. Atomic `SOFT_TIME` (S2).** `g1_regfile.v` was :105, :154-155; now :111,
:145, :161-165. `SOFT_TIME_H` writes go to `soft_time_h_sh`; the `SOFT_TIME_L`
write loads both bytes on one edge. Documented order: `_H` then `_L`; a read of
`_H` returns the byte in effect. Other registers checked: every other writable
register is one byte, so no other multi-byte write hazard exists. Remaining
multi-register ordering (e.g. `DAC_HARD` and `SENSE_OFS` written separately give
one intermediate threshold for one frame) is a host-sequencing matter, unchanged.
DAC lines: each write changes the source register on one `osc_clk` edge, but
`dac_soft/dac_hard` are **combinational** (hysteresis mux, 10-bit signed add,
saturation; `g1_trip_timer.v` :99-109), so they are not glitch-free: bits can
settle at different times for up to one combinational delay after the edge
(and after every `soft_armed` change when `HYST_EN` = 1). Not changed here;
registering them would cost 16 flops and one cycle. The MIM filter and the
INTERFACE ≥ 1 µs settle rule still apply (`DIGITAL.md` N4).

**4. `EN` digital deglitch (S5).** `g1_digital_top.v` was :49; now :58-82.
2-flop synchroniser + 7-bit history + `en_off` + `en_seen` (11 flops, reset
only by `por_n`). The core reset is asserted when `EN` was sampled low on 8
consecutive edges (measured 10 cycles after the fall, E5), or combinationally
from `EN` while `en_seen` = 0 (never seen high since power-up). `arst_n = por_n
& ~en_off & (en | en_seen)`; release stays synchronous (`rs0/rs1`), now 5
cycles after `EN` rise (E8), inside the unchanged 128-cycle host rule. A shift
register instead of a counter flushes an unknown power-up state (silicon) or X
(simulation) within 10 edges; `en_seen` powers up random with `por_n` tied high,
so the first reset is immediate or ≤ 10 cycles (E6 covers both deposited
states and X). The analog `EN` path (`en_core` into G1_GATE: gate off, latch
clear) is outside the macro and **unchanged and unfiltered**. Side effects:
(a) an `EN` low of 8-11 cycles resets the configuration but the latched trip
can survive (G1_GATE re-set by the not-yet-reset `trip_d`, re-adopted, cause
hard; E5); map §3 now asks for ≥ 2 µs for a deliberate reset; (b) a glitch no
longer restarts the inrush window; (c) with the oscillator dead, `EN` low no
longer resets the digital outputs (the analog `EN` path still turns `GATE` off).

**5. Defaults (M3, owner decision).** `g1_regfile.v` was :141, :144, :102; now
:148, :151, :107. `INRUSH` 0x14 → 0x02 (1024 cycles, 0.109 ms at 9.4 MHz),
`VERSION` 0x11 → 0x12; `MODE` stays 0x03 (`FAST_EN` = 0, host-selectable).
DAC and `SOFT_TIME` defaults unchanged. `FAST_EN` = 1 as the reset default was
implemented, evaluated and **reverted** (owner decision 2026-09-25): chip
co-simulation `eco_c_mid_r3` tripped through the fast path 0.214 µs after the
fault (`GATE` < 1 V 0.499 µs) against 1.049/1.334 µs on the digital path, but
the fast path acts on one comparator strobe, so 200 ns pulses that the
4-decision hard path rejects would trip, and the `FAST_EN` = 0 verification
matrix would no longer apply. A host that enables `FAST_EN` gets a fast path
that also acts inside the inrush window (E7).

**5a. Fast-path qualification after reset (found by the chip co-simulation).**
`g1_digital_top.v` now :105-112 and :151. The first chip-level run with 1-5
(`eco_c_mid`, below) tripped at `EN` rise: while the core is in reset `cmp_clk`
is static, the unstrobed hard comparator output sits at 1 (from 0.12 µs), and
with `FAST_EN` = 1 (then the default) the G1_GATE latch set as soon as `EN`
released its reset. Kept after the default was reverted, so the fast path is
safe whenever `FAST_EN` = 1 at a reset release.
The `fast_en` port is now `MODE.FAST_EN & fast_dly[2]`: 0 in reset, 1 from the
3rd edge after reset release (one edge after the first real hard decision;
E9: 3 cycles; chip level 0.8 µs after `EN` rise). `MODE` reads the register. Port
list unchanged; the port's meaning gains "and the core has been out of reset
for 3 edges". 3 flops.

**Cost.** Flops 1200 → 1222 (+22: EN filter 11, `SOFT_TIME_H` stage 8,
`fast_dly` 3, `inrush_done` 1, `OSC_EN` −1). Yosys generic synthesis (not the
LibreLane flow): 84 442 → 86 099 µm² cell area (+1 657 µm², +2.0 %).
Log: `build/g1_eco/synth_*.log` (gitignored; script `build/g1_eco/synth_cmp.sh`).
