## Concrete streamout repair

The original Magic/KLayout discrepancy is not merely harmless view metadata.
Generic analog PCell names collided during Magic's sequential macro import.
Its log states `Using pre-existing cell definition`; later macros thereby used
earlier macros' devices. For example, BGR's instance at local (39,112) resolves
to SENSE's `pmosHV$1`, bbox (−0.62,−0.62;77.08,6.62), while the correct KLayout
instance `pmosHV$1$3` is (−0.62,−0.62;5.3,5.62). BGR's overall bbox expands from
84 to 148.48 µm wide; the level shifter expands from 9.2 to 84.18 µm. The
retained original views have 142 changed child bboxes across BGR/T2F/GATE/LS
(including auxiliary child geometry as well as transistor/resistor PCells).
Exact per-macro/layer differences and cell transforms are preserved in
`streamout-namespaced-20260921/original_macro_differences.json`.

The repair namespaces private analog subcells before Magic import and preserves
macro top names and the digital standard-cell source policy. Source macro GDS
files remain untouched. Every renamed macro is reloaded and compared on every
stored polygon layer against its source before use. The original Magic Tcl
streamout script and original DEF are then replayed unchanged.

## Stock IO LVS and missing resistor recognition

Ran the unmodified PDK analog IO GDS/CDL in **deep** mode with strict top pins:

```sh
flow/run.sh python3 /foss/pdks/ihp-sg13g2/libs.tech/klayout/tech/lvs/run_lvs.py --layout /foss/pdks/ihp-sg13g2/libs.ref/sg13g2_io/gds/sg13g2_io.gds --netlist /foss/pdks/ihp-sg13g2/libs.ref/sg13g2_io/cdl/sg13g2_io.cdl --topcell sg13g2_IOPadAnalog --run_mode deep --run_dir /work/designs/g1-guardian/review/audits/io-lvs-deep-20260921 --top_lvl_pins --spice_comments
```

Result: **failed**, five unmatched child circuits and skipped parent; 7.544 s
in the wrapper log. Evidence: `io-lvs-deep-20260921/` contains exact manifest,
console, LVS database, extracted netlist and cross-reference summary. Deep mode
does not resolve the prior flat-mode mismatch.

The smallest localized defect is `sg13g2_SecondaryProtection/RR0`. CDL requests
an `rppd` between `pad` and `core`, W=1 µm/L=2 µm. The installed GDS contains
the corresponding unsilicided p-poly body but **zero PolyRes 128/0 polygons**
in this cell. The pinned `res_derivations.lvs` requires PolyRes intersected with
EXTBlock; absent recognition, the resistor is not extracted and `pad`/`core`
merge. This is a specific geometry/recognition mismatch, not a reason to alter
the deck or waive LVS.

An explicitly non-production diagnostic added a single 128/0 rectangle at
(0.94,1.37;1.94,3.37) µm in a scratch copy. The script asserted the rectangle
lies within the existing GatPoly/SalBlock body and that the entire analog-pad
hierarchy changed only on 128/0, by **2.0 µm²**. The installed PDK and delivered
chip GDS were untouched.

```sh
flow/run.sh python3 designs/g1-guardian/review/audits/io_recognition_probe.py --work build/scratch/io-recognition-20260921 --report designs/g1-guardian/review/audits/io-recognition-20260921
```

The unmodified deck now extracts:

```spice
R$3 pad core $1 rppd w=1u l=2u ps=0u b=0 m=1
```

The R0 mismatch and merged pad/core net disappear. SecondaryProtection
unmatched counts fall from 5 nets/3 devices/3 pins to 2 nets/1 device/2 pins.
**The overall diagnostic still fails:** five unmatched circuits remain and the
parent is skipped. The residual SecondaryProtection tap has extracted area
9.0304 µm²/perimeter 53.12 µm versus CDL 9.03 µm²/12.02 µm; the substrate/tap
comparison and separate clamp/diode circuits remain unresolved.

IHP's [layer table](https://ihp-open-pdk-docs.readthedocs.io/en/latest/layout_rules/02_layer_table.html)
describes PolyRes 128/0 as a resistor marking layer. The diagnostic adds only
that recognition layer, not GatPoly, diffusion, implant or metal. This does
not establish a foundry-approved mask-processing change or authorize promotion
of the diagnostic view. Production annotation repair, its DRC, complete IO
CDL correspondence and full assembled IO-inclusive LVS are **not run**.

## Preventing false-success LVS invocations

The new deep stock-cell run returned **process exit 0 despite an explicit LVS
FAIL**. The prior local `run_core_lvs.sh` additionally piped through `tee`/`tail`
without `pipefail`, which could hide preparation/extractor failures.

The helper now enables `set -euo pipefail`, quotes paths, retains the complete
console, and requires the PDK's explicit `Comparison mode: PASS (netlists
match).` summary as well as successful processes. No comparison settings or
PDK code changed. Existing core LVS evidence remains its prior explicit match;
new full core extraction was **not run**, since no chip geometry changed.

`test_lvs_wrapper.py` exercised six scenarios: successful explicit PASS, failed
CDL preparation, failed GDS preparation, failed solver exit even after a PASS
line, zero-exit mismatch, and zero-exit incomplete output. All passed; exact

## Antenna and recommended pad shapes

`audit_pad_markers.py` located the preserved markers on the actual delivered
GDS and traced local poly/contact/via/metal connectivity without connecting
through diffusion/transistor channels. The nine antenna markers map to the
three EN/SCLK/SDI input-pad receiver gates; all trace to the cell's **VDD** net.
Full coordinates, cell transforms, ratios and deck hashes are in
`pad-markers-20260921.json`.

The unmodified Ant.e rule tests cumulative metal-area/gate-area with a binary
`has_diode` condition. The markers already have diode protection recognized.
Adding an unrelated signal diode or assuming a supply-gate exemption would
not resolve this evidence. The current deck has no such waiver. Changing the
receiver gate tie, qualified pad cell or connected supply/gate geometry would
require electrical/power-sequence, DRC/LVS and antenna revalidation. No such
design change or new antenna run was made; antenna remains **failed**.

The 60 recommended pad markers are specific **4 µm missing exit strips**
relative to the rule's 7 µm requirement and the cells' 3 µm stub. TM1 has
24 markers of 70×4 µm (rotated by side). TM2 has 20 full-width 70×4 µm
markers and 16 fragments 2.5/5.0/5.01×4 µm. Example north-edge missing strip:
(808,1202;878,1206) µm. These polygons define a minimal candidate extension of
the corresponding same-net upper-metal pad exits. They are only a proposed
geometric repair: adding them, verifying same-net connectivity/spacing, rerunning
recommended and hard DRC/density/antenna, and updating the final GDS are
**not run**. The JSON records each missing polygon and its relation to existing
metal so the next edit is reproducible.

The actual outstanding physical gates are therefore explicit: production
IO-library recognition/substrate/device correspondence, VDD-connected receiver
antenna ratios, pad exit extensions and final assembled-view regressions.
