# Native ARM simulation runtime qualification

Status: **runtime qualification failed** (one of six block fixtures does not complete). The accepted baseline remains the recorded
ngspice 46 amd64 image; no completed campaign is reclassified by a tool upgrade.

The ARM laptop currently runs that baseline under x86 emulation. A separate ARM
Linux runtime is being built, initially capped at two CPUs and 8 GiB, while the
baseline campaigns continue. Individual block simulations use one solver thread;
independent cases run concurrently. The integrated 4 us fixture produced identical
saved numeric waves with 1/2/4 threads, with observed wall times 140.2/130.2/150.2 s.
These single, concurrently loaded measurements are not a general speed ranking.

## 2026-09-21 comparison result

Native image `g1-sim-arm64:20260921`, observed content ID
`sha256:ab853b72c0b95f467d562afc77b09cfb7093a87910e26bf671ad46566dadd82e`,
contains both versions at `/opt/ngspice-46` and `/opt/ngspice-47`.
The existing image tag/default remains unchanged.

Five completed fixtures satisfy the comparison tolerances: BGR noise/PSRR,
BGR seed42001 temperature sweep, SENSE noise, OSC transient, GATE core-first.
For these fixtures ARM46 and ARM47 saved numeric results are identical.
Both ARM versions fail the IO-first transient at6.31691us in a pad diode;
the baseline x86 runtime completes and reports the unsafe GATE-high behavior.
An incomplete native run cannot supersede that electrical failure.

See `designs/g1-guardian/review/runtime/arm46_vs_arm47_20260921.json` and
`x86_46_vs_arm46_20260921.json`. Tolerances are recorded in each result.
The first x86 comparison batch has a5s polling floor in wall measurements;
`run_bounded.py` now waits for child exit between progress snapshots, with
all six existing watchdog/evidence tests passing. Rebenchmark before quoting
speed ratios for short runs. Integrated4us mixed-signal ARM qualification
is still running; there is no demonstrated overall throughput benefit yet.

The model source tree also contains a pre-existing `r3_cmc-patched.va` with
conditional SOA warning guards. The native build compiles `r3_cmc.va` itself,
without edits. The baseline compiled model contains SOA warning strings too;
the mere presence of the alternate source does not establish which was used.
New integrated SOA warnings occur during dynamic gmin startup; terminal limits
need evaluation on accepted operating/transient points.

Integrated ARM46 SPARSE4us prefix completed211.99s and passed endpoint/finite
wave checks, versus130.17s for the earlier x86 two-thread run under different
concurrent load. It has not shown a throughput advantage. Both ARM46 and
x86 KLU/trap4us pilots fail at3.04841us (`gate_core`, timestep too small);
ARM47 KLU/gear also fails at the same point. These failures are retained under
`g1_top/sim/logs/*klu*20260921*.json`; KLU is not adopted.

A corrected-timing x86 repetition completed BGR noise0.445s, BGR MC0.480s,
SENSE noise1.109s, OSC15.302s, core-first3.126s. Native results were respectively
0.294/0.282/0.735/10.681/2.062s. These are single concurrently loaded observations;
selected standalone tasks benefit, but the integrated path does not establish
a general native speedup. Image package/compiler/binary records are retained at
`review/runtime/native-build-20260921` under the design.

`Dockerfile` and `build-runtime.sh` capture a reproduction recipe; the image was
actually built with the preserved manual commands/logs. The Dockerfile itself
has not been rebuilt end-to-end. Verify the legacy source image content ID
before rebuilding; its tag in the recipe must resolve to the documented baseline.
